## How to Get Started

### Step 1: Apply Database Migrations

## Database Schema (Quick View)

### New: Coupon Model
- `code` - Coupon code (unique)
- `discount_type` - 'percentage' or 'fixed'
- `discount_value` - Amount or %
- `is_for_first_order` - First-time buyers only
- `usage_limit_per_user` - How many times user can use
- `min_order_amount` - Minimum order requirement
- `is_active` - Enable/disable coupon

### New: CouponUsage Model
- `coupon` - Which coupon used
- `user` - Which user used it
- `order` - Which order it was used with
- `used_at` - When it was used

### Updated: Order Model
- `coupon_code` - Code that was applied (new field)
- `discount_amount` - Amount saved (new field)

## Common Questions

**Q: Will old orders work?**
✅ Yes! coupon_code and discount_amount are nullable.

**Q: Can I disable auto-refresh?**
✅ Yes! Modify `7000` in `static/dashboard_standalone.html` or remove the interval.

**Q: Can I change discount per user?**
✅ Yes! Uses_limit_per_user field in Coupon model.

**Q: Does this use Django Channels?**
❌ No! Uses simple AJAX polling (5-7% server load).

**Q: Is it secure?**
✅ Yes! All validation happens server-side. Client can't modify discount.

**Q: What about existing reports?**
✅ Dashboard still works! New metrics are added.

**Q: Can I export coupon usage?**
✅ Yes! Django admin has full filtering and export.

## Production Tips

1. **Auto-Refresh Rate**: Change `7000` (ms) to match your needs
   - `3000` = 3s (high server load)
   - `7000` = 7s (recommended)
   - `15000` = 15s (low server load)

2. **Dashboard Authentication**: Add `@login_required` decorator to `/dashboard/` view in production

3. **Coupon Strategy**: Create coupons strategically
   - First-order: 10-15% to get new users
   - Bulk: 20-30% on min ₹1000+ orders
   - Flash: Time-limited high-value discounts

4. **Monitoring**: Check `/admin/store/couponusage/` regularly to see:
   - Which coupons are popular
   - Average discount given
   - Customer acquisition rate
